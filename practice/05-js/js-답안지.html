문제 1. 변수와 템플릿 리터럴

문제

주어진 변수 name 과 views 를 써서 아래 한 줄을 console.log 로 찍으시오. 템플릿 리터럴(`)을 쓰십시오.

김하나 기자의 기사 — 조회수 1845회

(검사는 변수 값을 바꿔서도 한 번 더 돌립니다 — 글자를 그대로 적으면 걸립니다)

화면에 같은 글자가 찍히니 맞은 것 같습니다. 하지만 변수가 바뀌면 따라가지 못합니다.

문제 2. + 와 - 의 차이

문제

다음 두 줄은 무엇을 찍습니까?

console.log("3" + 1);
console.log("3" - 1);

① 31 과 2
② 4 와 2
③ 31 과 31
④ 4 와 NaN

정답 — ① 31 과 2

실제로 돌려 보면

31
2

해설

+ 는 한쪽이라도 문자열이면 이어 붙입니다 — "3" + 1 은 "31". - 는 이어 붙이는 뜻이 없어서 둘 다 숫자로 바꿔 계산합니다 — 2. 입력칸의 값(input.value)은 늘 문자열이라, 더하기 전에 Number(...) 로 바꿔야 합니다.

흔한 오답 — ②

둘 다 숫자 계산이라고 생각하기 쉽습니다. + 는 한쪽이 글자면 «이어 붙이기»가 됩니다.

문제 3. 글자를 숫자로

문제

입력칸에서 받은 두 값(문자열)을 더한 숫자를 돌려주는 함수 addStrings(a, b) 를 만드시오.

  • addStrings("10", "5") → 15

정답

function addStrings(a, b) {
  return Number(a) + Number(b);
}

해설

Number("10") 은 숫자 10 입니다. 바꾼 뒤에 더해야 15 가 됩니다. parseInt 도 되지만 소수점 아래를 버리므로(parseInt("1.5") → 1) 이 문제에는 Number(또는 parseFloat)가 맞습니다.

검사 항목 (3개)

  1. addStrings("10", "5") → 15
  2. addStrings("3", "4") → 7 · ("0", "0") → 0
  3. 소수도 된다 — addStrings("1.5", "2") → 3.5

흔한 오답 — 「addStrings("10", "5") → 15」에서 걸립니다

더하기만 쓰면 "105" 가 됩니다 — 문자열끼리는 이어 붙이기입니다.

function addStrings(a, b) {
  return a + b;
}

문제 4. == 와 ===

문제

다음 중 결과가 true 인 것은?

① "1" === 1
② null === undefined
③ 0 == ""
④ NaN === NaN

정답 — ③ 0 == ""

실제로 돌려 보면

false false true false

해설

== 는 타입이 다르면 바꿔서 비교합니다 — 0 == "" 는 "" 가 0 으로 바뀌어 true. 이런 «몰래 바꾸기» 때문에 헷갈립니다. === 는 바꾸지 않습니다 — 타입이 다르면 무조건 false. 늘 === 를 쓰십시오. (NaN 은 자기 자신과도 같지 않습니다 — Number.isNaN(x) 로 봅니다.)

흔한 오답 — ②

null == undefined 는 true 라서 === 도 그럴 것 같습니다. === 는 타입까지 같아야 합니다.

문제 5. if … else if

문제

점수를 받아 등급을 돌려주는 grade(score) 를 만드시오.

  • 90 이상 "A" · 80 이상 "B" · 70 이상 "C" · 그 밖에는 "F"

정답

function grade(score) {
  if (score >= 90) return "A";
  else if (score >= 80) return "B";
  else if (score >= 70) return "C";
  return "F";
}

해설

파이썬의 elif 가 JS 에서는 else if 입니다. 위에서부터 처음 맞는 곳에서 멈추므로 큰 점수부터 묻습니다. 「이상」은 >=, 「초과」는 > — 경계값을 꼭 넣어 시험해 보십시오.

검사 항목 (3개)

  1. 100 → A · 85 → B · 75 → C · 30 → F
  2. 경계값 — 90 → A · 80 → B · 70 → C
  3. 경계 바로 아래 — 89 → B · 69 → F

흔한 오답 — 「경계값 — 90 → A · 80 → B · 70 → C」에서 걸립니다

「90 이상」을 > 90 으로 옮기는 실수입니다. 경계값(90 · 80 · 70)에서만 틀려서 눈에 잘 안 띕니다.

function grade(score) {
  if (score > 90) return "A";
  else if (score > 80) return "B";
  else if (score > 70) return "C";
  return "F";
}

문제 6. 나머지 연산자 %

문제

정수가 짝수이면 true, 홀수이면 false 를 돌려주는 isEven(n) 을 만드시오. 음수도 들어옵니다.

정답

function isEven(n) {
  return n % 2 === 0;
}

해설

% 는 나눈 나머지입니다. 짝수는 2 로 나눈 나머지가 0 입니다. 🔴 JS 의 % 는 왼쪽 수의 부호를 따라갑니다 — -3 % 2 는 -1(파이썬은 1). 그래서 「=== 1 이면 홀수」는 음수에서 틀립니다. === 0 으로 짝수를 묻는 쪽이 안전합니다.

검사 항목 (2개)

  1. 4 → true · 7 → false · 0 → true
  2. 음수 — -4 → true · -3 → false

흔한 오답 — 「음수 — -4 → true · -3 → false」에서 걸립니다

「홀수는 나머지가 1」이라고 외우기 쉽습니다. JS 에서 -3 % 2 는 -1 이라 음수 홀수가 짝수로 나옵니다.

function isEven(n) {
  return n % 2 === 1 ? false : true;
}

문제 7. switch

문제

요일 번호(0 = 일요일 … 6 = 토요일)를 받아 한 글자 요일을 돌려주는 dayName(n) 을 switch 로 만드시오.

  • 0 → "일", 1 → "월", … 6 → "토"
  • 그 밖의 값 → "없음"

정답

function dayName(n) {
  switch (n) {
    case 0: return "일";
    case 1: return "월";
    case 2: return "화";
    case 3: return "수";
    case 4: return "목";
    case 5: return "금";
    case 6: return "토";
    default: return "없음";
  }
}

해설

switch 는 값 하나를 여러 case 와 === 로 비교합니다. 어느 것과도 같지 않으면 default 로 갑니다. return 을 쓰지 않는 case 에는 break 를 빠뜨리지 마십시오 — 없으면 아래 case 까지 이어서 실행됩니다.

검사 항목 (2개)

  1. 0 → 일 · 3 → 수 · 6 → 토
  2. 그 밖의 값 — 7 → 없음 · -1 → 없음

흔한 오답 — 「그 밖의 값 — 7 → 없음 · -1 → 없음」에서 걸립니다

0~6 만 시험해 보면 다 맞습니다. 맞는 case 가 없을 때를 잊으면 undefined 가 나옵니다.

function dayName(n) {
  switch (n) {
    case 0: return "일";
    case 1: return "월";
    case 2: return "화";
    case 3: return "수";
    case 4: return "목";
    case 5: return "금";
    case 6: return "토";
  }
}

문제 8. for 반복

문제

1부터 n 까지의 합을 돌려주는 sumTo(n) 을 for 로 만드시오. n 이 0 이면 0 입니다.

정답

function sumTo(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

해설

for (시작; 조건; 증가) — 조건이 참인 동안 돕니다. 「n 까지」는 i <= n 입니다. 합을 모을 변수(total)는 반복 바깥에서 let 으로 만듭니다. 안에서 만들면 돌 때마다 0 으로 돌아갑니다.

검사 항목 (2개)

  1. sumTo(10) → 55 · sumTo(100) → 5050
  2. sumTo(1) → 1 · sumTo(0) → 0

흔한 오답 — 「sumTo(10) → 55 · sumTo(100) → 5050」에서 걸립니다

i < n 은 n 을 빼고 멈춥니다 — 반복의 끝 경계를 하나 어긋나게 쓰는 가장 흔한 실수입니다.

function sumTo(n) {
  let total = 0;
  for (let i = 1; i < n; i++) {
    total += i;
  }
  return total;
}

문제 9. while 반복

문제

n 부터 1까지 거꾸로 센 배열을 돌려주는 countdown(n) 을 while 로 만드시오.

  • countdown(3) → [3, 2, 1] · countdown(0) → []

정답

function countdown(n) {
  const result = [];
  while (n >= 1) {
    result.push(n);
    n--;
  }
  return result;
}

해설

while (조건) 은 조건이 참인 동안 돕니다. 안에서 조건을 바꾸지 않으면(n-- 을 빠뜨리면) 끝나지 않습니다 — 이 연습장은 3초 뒤 멈추고 알려 줍니다. push 는 배열 끝에 하나를 넣습니다. const 배열이어도 안의 내용은 바꿀 수 있습니다.

검사 항목 (2개)

  1. countdown(3) → [3, 2, 1]
  2. countdown(1) → [1] · countdown(0) → []

흔한 오답 — 「countdown(3) → [3, 2, 1]」에서 걸립니다

「0 이 될 때까지」를 n >= 0 으로 쓰면 0 까지 들어갑니다.

function countdown(n) {
  const result = [];
  while (n >= 0) {
    result.push(n);
    n--;
  }
  return result;
}

문제 10. for…of

문제

주어진 배열 sections 를 for…of 로 돌며 번호를 붙여 한 줄씩 찍으시오.

1. 정치
2. 경제
3. 사회

(검사는 다른 배열로도 돌립니다)

주어진 JS — 이미 들어 있습니다(같은 이름을 다시 선언하지 마십시오)

const sections = ["정치", "경제", "사회"];

정답

let no = 1;
for (const s of sections) {

for (const x of 배열) 은 배열의 값을 하나씩 꺼냅니다(파이썬의 for x in 리스트). 번호가 필요하면 바깥에 세는 변수를 두거나 sections.forEach((s, i) => …) 의 i + 1 을 씁니다. 🔴 for…in 은 값이 아니라 번호(키) 를 꺼냅니다 — 배열에는 for…of 를 쓰십시오.

검사 항목 (2개)

    1. 정치 · 2. 경제 · 3. 사회
  2. 다른 배열 — ["IT", "문화"] → 1. IT · 2. 문화

흔한 오답 — 「1. 정치 · 2. 경제 · 3. 사회」에서 걸립니다

배열의 번호(인덱스)가 0 부터라 그대로 찍으면 0. 정치 가 됩니다. 사람에게 보이는 번호는 1 부터입니다.

let no = 0;
for (const s of sections) {
  console.log(`${no}. ${s}`);
  no++;
}

문제 11. break

문제

숫자 배열에서 처음으로 나오는 음수의 위치(인덱스)를 돌려주는 firstNegative(nums) 를 만드시오. 음수가 없으면 -1 입니다. 반복과 break(또는 return)를 쓰십시오.

정답

function firstNegative(nums) {
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] < 0) return i;
  }
  return -1;
}

해설

찾았으면 그 자리에서 멈춰야 「처음」입니다. 함수 안이면 return i 가 반복과 함수를 한꺼번에 끝내고, 반복만 끝내려면 break 를 씁니다. 배열 메서드로는 nums.findIndex((n) => n < 0) 한 줄입니다(4일차 find 의 형제).

검사 항목 (2개)

  1. [3, -1, -5] → 1 (처음 것)
  2. [-2] → 0 · [1, 2] → -1 · [] → -1

흔한 오답 — 「[3, -1, -5] → 1 (처음 것)」에서 걸립니다

찾아도 멈추지 않으면 끝까지 돌며 덮어써서 «마지막» 음수의 위치가 남습니다.

function firstNegative(nums) {
  let found = -1;
  for (let i = 0; i < nums.length; i++) {
    if (nums[i] < 0) found = i;
  }
  return found;
}

문제 12. || 와 ??

문제

값이 없으면(null · undefined) "없음" 을, 있으면 그 값을 그대로 돌려주는 withDefault(value) 를 만드시오. 🔴 0 과 빈 글자 "" 는 «있는 값»입니다 — 그대로 돌려줍니다.

정답

function withDefault(value) {
  return value ?? "없음";
}

해설

a || b 는 a 가 거짓 같은 값(0 · "" · false · null · undefined · NaN)이면 b 입니다. a ?? b 는 a 가 null · undefined 일 때만 b 입니다. 조회수 0 · 빈 제목처럼 «0 도 값»인 자리에는 ?? 를 쓰십시오.

검사 항목 (2개)

  1. null · undefined → "없음" · "김하나" → "김하나"
  2. 0 → 0 · "" → "" · false → false (있는 값)

흔한 오답 — 「0 → 0 · "" → "" · false → false (있는 값)」에서 걸립니다

|| 로 기본값을 넣는 코드를 많이 봅니다. || 는 0 · "" · false 도 «없다»로 봅니다.

function withDefault(value) {
  return value || "없음";
}

문제 13. 화살표 함수 · 숫자 꾸미기

문제

조회수를 받아 세 자리마다 쉼표를 넣고 회 를 붙인 글자를 돌려주는 formatViews 를 화살표 함수로 만드시오.

중괄호를 쓰는 순간 «자동 return» 이 사라집니다. 계산은 하고 버려서 undefined 가 나옵니다(JS 2일차 🔴).

const formatViews = (n) => { n.toLocaleString("ko-KR") + "회"; };

문제 14. 문자열 다듬기 — trim · toLowerCase

문제

검색어를 비교하기 좋게 다듬는 cleanInput(s) 를 만드시오 — 앞뒤 공백을 없애고 영어는 소문자로 바꿉니다.

  • cleanInput(" Hello JS ") → "hello js"

정답

function cleanInput(s) {
  return s.trim().toLowerCase();
}

해설

문자열 메서드는 원래 글자를 고치지 않고 새 글자를 돌려줍니다. 그래서 s.trim() 만 쓰고 버리면 아무 일도 안 일어납니다 — 결과를 받아 쓰거나 이어서(.trim().toLowerCase()) 부르십시오. 한글에는 대소문자가 없어 그대로입니다.

검사 항목 (2개)

  1. " Hello JS " → "hello js"
  2. "AI" → "ai" · " " → "" · "금리" → "금리"

흔한 오답 — 「" Hello JS " → "hello js"」에서 걸립니다

s.trim() 이 s 를 고친다고 생각하기 쉽습니다. 문자열은 바뀌지 않고, 다듬은 «새 글자»를 돌려줄 뿐입니다.

function cleanInput(s) {
  s.trim();
  return s.toLowerCase();
}

문제 15. 문자열 자르기 — length · slice

문제

제목이 max 글자보다 길면 앞의 max 글자만 남기고 … 를 붙이고, 아니면 그대로 돌려주는 shorten(title, max) 를 만드시오.

문제 29. Object.entries

문제

객체를 받아 키=값 을 & 로 이은 글자(주소 뒤에 붙는 질의 문자열)를 만드는 toQuery(params) 를 만드시오. 글자를 바꾸는(인코딩) 일은 하지 않습니다.

  • toQuery({ page: 2, size: 10 }) → "page=2&size=10" · toQuery({}) → ""

정답

function toQuery(params) {
  return Object.entries(params).map(([k, v]) => `${k}=${v}`).join("&");
}

해설

Object.entries(obj) 는 [키, 값] 짝의 배열입니다 — [["page", 2], ["size", 10]]. 배열이 되었으니 map 으로 "page=2" 를 만들고 join("&") 으로 사이에만 & 를 넣습니다. Object.keys(키만) · Object.values(값만)도 함께 기억해 두십시오.

검사 항목 (2개)

  1. { page: 2, size: 10 } → "page=2&size=10"
  2. { q: "금리" } → "q=금리" · {} → ""

흔한 오답 — 「{ page: 2, size: 10 } → "page=2&size=10"」에서 걸립니다

반복하며 & 를 붙이면 맨 끝에도 하나가 남습니다.

function toQuery(params) {
  let s = "";
  for (const k in params) s += `${k}=${params[k]}&`;
  return s;
}

console.log([10, 9, 1, 100].sort());

① [1, 9, 10, 100]
② [100, 10, 9, 1]
③ [1, 10, 100, 9]
④ [10, 9, 1, 100] — 숫자는 비교 함수 없이 정렬하지 않는다

[1, 10, 100, 9]

흔한 오답 — ①

숫자 배열이니 숫자 크기대로 줄 설 것 같습니다. 비교 함수가 없으면 모두 «글자»로 바꿔 사전 순서로 세웁니다.

문제 37. 숫자 정렬

문제

숫자 배열을 작은 수부터 정렬한 새 배열을 돌려주는 sortNumbers(nums) 를 만드시오. 넘겨받은 배열은 바꾸지 않습니다.

정답

function sortNumbers(nums) {
  return [...nums].sort((a, b) => a - b);
}

해설

(a, b) => a - b — 결과가 음수면 a 가 앞, 양수면 b 가 앞입니다. 그래서 작은 수부터 섭니다. 복사([...nums])를 먼저 하는 이유는 35번과 같습니다.

검사 항목 (2개)

  1. [10, 9, 1, 100] → [1, 9, 10, 100]
  2. [3, -2, 0] → [-2, 0, 3] · 넘겨준 배열은 그대로

흔한 오답 — 「[10, 9, 1, 100] → [1, 9, 10, 100]」에서 걸립니다

36번의 함정입니다 — [3, 1, 2] 처럼 한 자리 수로만 시험하면 맞게 나옵니다.

function sortNumbers(nums) {
  return [...nums].sort();
}

문제 58. Promise.all — 한꺼번에

문제

주소 배열을 받아 모두 한꺼번에 받아온 JSON 을 같은 순서의 배열로 돌려주는 async 함수 loadAll(urls) 를 만드시오. 가짜 서버는 주소마다 150ms 씩 걸립니다 — 셋을 하나씩 받으면 450ms, 한꺼번에 받으면 150ms 쯤입니다. 한꺼번에 받으십시오.

가짜 서버 — fetch 는 인터넷 대신 이 표대로 답합니다. 그 밖의 주소는 404

주소 답
a.json 200 · JSON 1 · 150ms 뒤
b.json 200 · JSON 2 · 150ms 뒤
c.json 200 · JSON 3 · 150ms 뒤

정답

async function loadAll(urls) {
  return Promise.all(urls.map(async (url) => {
    const res = await fetch(url);
    return res.json();
  }));
}

해설

Promise.all([쪽지들]) 은 쪽지를 한꺼번에 기다렸다가, 모두 끝나면 결과를 넣은 순서대로 배열로 줍니다(먼저 끝난 순서가 아님). urls.map(async …) 이 쪽지 배열을 만들고 — 이때 이미 셋 다 출발합니다 — Promise.all 이 모아서 기다립니다. 🔴 forEach 안의 await 는 아무도 기다려 주지 않습니다(7일차).

검사 항목 (3개)

  1. [a, b, c] → [1, 2, 3] (순서대로)
  2. 한꺼번에 받는다 — 셋에 300ms 안
  3. 빈 배열 → []

흔한 오답 — 「한꺼번에 받는다 — 셋에 300ms 안」에서 걸립니다

결과는 같습니다. 하지만 하나가 끝나야 다음을 시작해서 주소가 늘수록 기다리는 시간이 쌓입니다(7일차 「하나씩 vs 한꺼번에」).

async function loadAll(urls) {
  const out = [];
  for (const url of urls) {
    const res = await fetch(url);
    out.push(await res.json());
  }
  return out;
}

문제 59. 종합 — 받아서 그리기 (로딩 · 성공 · 실패)

문제

페이지가 열리면 news.json 을 받아 그리시오. 화면의 상태는 셋입니다(8일차).

  • 받는 동안 #status: 불러오는 중…
  • 성공: #list 에 기사마다 <li>(글자는 제목) — 조회수가 많은 순 · #status: 8건(받은 건수)
  • 실패(응답이 200번대가 아님): #status: 불러오지 못했습니다 (HTTP 500) 처럼 상태 번호

HTML (고정)

<p id="status"></p>
<ul id="list"></ul>

가짜 서버 — fetch 는 인터넷 대신 이 표대로 답합니다. 그 밖의 주소는 404

주소 답
news.json 200 · JSON 배열 8건 · 120ms 뒤

정답

async function start() {
  const status = document.querySelector("#status");
  const list = document.querySelector("#list");
  status.textContent = "불러오는 중…";
  const res = await fetch("news.json");
  if (!res.ok) {
    status.textContent = `불러오지 못했습니다 (HTTP ${res.status})`;
    return;
  }
  const data = await res.json();
  const sorted = [...data].sort((a, b) => b.views - a.views);
  list.innerHTML = "";
  for (const a of sorted) {
    const li = document.createElement("li");
    li.textContent = a.title;
    list.append(li);
  }
  status.textContent = `${data.length}건`;
}

start();

해설

9일차의 한 바퀴입니다 — 받고(fetch) → 확인하고(res.ok) → 바꾸고(sort) → 그린다(비우고 · 그린다). 그리고 화면에는 상태가 셋입니다: 로딩 · 성공 · 실패. 🔴 실패를 화면에 알리지 않으면 사용자는 「불러오는 중…」만 보며 기다립니다. 콘솔의 빨간 줄은 사용자에게 안 보입니다.

검사 항목 (3개)

  1. 받는 동안 「불러오는 중…」
  2. 성공 — 조회수 많은 순 8건 · 「8건」
  3. 실패(500) — 「불러오지 못했습니다 (HTTP 500)」

흔한 오답 — 「실패(500) — 「불러오지 못했습니다 (HTTP 500)」」에서 걸립니다

성공만 시험하면 완벽합니다. 서버가 500 을 주면 몸통(「서버 오류」)을 JSON 으로 읽다 멈추고, 화면은 「불러오는 중…」에 영원히 머뭅니다.
