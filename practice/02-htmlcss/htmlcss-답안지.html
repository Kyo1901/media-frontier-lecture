문제 1. 이름 있는 상자 고르기

개념 확인 · 모두 고르기

문제

화면에서는 모두 「아무 모양 없는 상자」로 보이지만, 이름에 뜻이 있는 상자(시맨틱 태그)가 있습니다. 다음 중 시맨틱 태그를 모두 고르시오.

① <div>
② <nav>
③ <span>
④ <article>
⑤ <footer>
⑥ <section>

정답 — ② ④ ⑤ ⑥

해설

nav(메뉴) · article(혼자 떼어 내도 말이 되는 글 한 편) · footer(바닥) · section(주제로 묶인 구역)은 태그 이름이 곧 뜻입니다. 화면 읽기 프로그램 · 검색 엔진이 이 이름을 읽습니다. div 는 구역(블록), span 은 글자 줄 안(인라인)의 뜻 없는 상자입니다. 모양을 잡으려고 묶을 때만 씁니다.

흔한 오답 — ① ② ④ ⑤ ⑥

div 도 「구역을 나누는 상자」라 함께 고르기 쉽습니다. 하지만 div 는 이름에 아무 뜻이 없는 상자입니다 — 그래서 뜻이 없을 때 쓰는 «마지막 수단»입니다.

문제 2. strong 과 b

개념 확인 · 하나 고르기

문제

기사 본문에서 「오늘 오후 3시부터 운행 중단」은 독자가 꼭 알아야 할 중요한 내용이라 굵게 보이게 하려 합니다. 가장 알맞은 것은?

① <b> — 굵게 보이기만 하면 된다
② <strong> — 「중요하다」는 뜻을 담는다
③ <h3> — 크고 굵게 보인다
④ <br> 으로 앞뒤를 끊어 눈에 띄게 한다

정답 — ② <strong> — 「중요하다」는 뜻을 담는다

해설

<b> 와 <strong> 은 화면이 같습니다. 다른 것은 뜻입니다 — <strong> 은 「중요하다」를 담아 화면 읽기 프로그램이 힘주어 읽고, <b> 는 「굵게 보일 뿐」입니다. <h3> 은 제목이라 문서의 목차(구조)가 바뀌고, <br> 은 줄을 바꿀 뿐 강조가 아닙니다.

흔한 오답 — ①

화면에서는 <b> 와 <strong> 이 똑같이 굵습니다. 그래서 짧은 <b> 를 고르기 쉽습니다.

문제 3. 순위 목록

코드 작성 · HTML (body 안에 들어갈 내용)

문제

「많이 본 기사」 1~3위를 순서가 있는 목록으로 만드시오. 항목은 차례대로 금리 동결, 신작 개봉, 폭설 주의보 입니다.

정답

<ol>
  <li>금리 동결</li>
  <li>신작 개봉</li>
  <li>폭설 주의보</li>
</ol>

해설

ul 은 순서 없는 목록(점), ol 은 순서가 있는 목록(번호)입니다. 번호를 글자로 직접 쓰지 않아도 ol 이 1, 2, 3 을 붙여 줍니다. 순위 · 절차처럼 순서를 바꾸면 뜻이 달라지는 것은 ol 입니다.

검사 항목 (3개)

  1. ol 안에 li 가 3개
  2. 순서 없는 목록(ul)을 쓰지 않았다
  3. 항목이 금리 동결 / 신작 개봉 / 폭설 주의보 차례

흔한 오답 — 「ol 안에 li 가 3개」에서 걸립니다

목록이면 ul 부터 떠올리기 쉽습니다. 순위처럼 순서에 뜻이 있으면 ol 입니다.

<ul>
  <li>금리 동결</li>
  <li>신작 개봉</li>
  <li>폭설 주의보</li>
</ul>

문제 4. 이름–값 목록

코드 작성 · HTML (body 안에 들어갈 내용)

문제

영화 「겨울 항구」의 정보를 이름–값 목록(dl)으로 만드시오.

  • 감독 — 서유진
  • 개봉 — 2024-12-18
  • 출연 — 한도윤, 이서아 (이름 하나에 값 둘 — 값마다 dd 를 따로)

정답

<dl>
  <dt>감독</dt><dd>서유진</dd>
  <dt>개봉</dt><dd>2024-12-18</dd>
  <dt>출연</dt>
  <dd>한도윤</dd>
  <dd>이서아</dd>
</dl>

해설

dl 안에 dt(이름)와 dd(값)를 차례로 씁니다. 이름 하나에 값이 여럿이면 dd 를 이어서 여러 개 둡니다 — 반대로 값 하나에 이름이 여럿(dt 둘 다음 dd 하나)도 됩니다. 쉼표로 한 칸에 몰아 쓰면 화면은 비슷해도 「값이 둘」이라는 정보가 사라집니다.

검사 항목 (4개)

  1. dl 이 하나 있다
  2. dt 3개 · dd 4개
  3. 감독=서유진 · 개봉=2024-12-18
  4. 출연 다음에 값(dd)이 둘 — 한도윤 / 이서아

흔한 오답 — 「출연 다음에 값(dd)이 둘 — 한도윤 / 이서아」에서 걸립니다

dt 와 dd 는 꼭 한 쌍씩이라고 생각하기 쉽습니다. 값이 여럿이면 dd 를 여럿 둘 수 있고, 그래야 「출연자가 두 명」이라는 것이 태그로 드러납니다.

<dl>
  <dt>감독</dt><dd>서유진</dd>
  <dt>개봉</dt><dd>2024-12-18</dd>
  <dt>출연</dt><dd>한도윤, 이서아</dd>
</dl>

문제 5. 문서 뼈대

코드 작성 · HTML 문서 전체

문제

다음 조건을 지키는 HTML 문서를 처음부터 작성하시오.

  • 문서 형식 선언(<!DOCTYPE html>) · 언어는 한국어(lang="ko") · 문자 인코딩은 UTF-8
  • 탭에 보이는 제목은 주간 편성표
  • 같은 폴더의 css 폴더 안에 있는 style.css 를 이어 붙일 것
  • 본문에 h1 하나: 주간 편성표

정답

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>주간 편성표</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
  <h1>주간 편성표</h1>
</body>
</html>

해설

<link rel="stylesheet" href="…"> 는 <head> 안에 둡니다. rel 은 「이 파일은 스타일 시트다」, href 는 「어디에 있나」입니다 — 둘 중 하나만 틀려도 아무 오류 없이 CSS 가 안 먹습니다(F12 의 Network 탭에서 확인). <!DOCTYPE html> 을 빠뜨리면 브라우저가 호환 모드로 그려 표 안의 글자 크기 · 줄 높이 같은 것이 옛 브라우저 방식으로 바뀝니다. 글자는 똑같이 보여서 알아차리기 어렵습니다.

검사 항목 (5개)

  1. 맨 첫 줄이 문서 형식 선언()
  2. html 의 lang 이 ko · meta charset 이 utf-8
  3. 탭 제목이 「주간 편성표」
  4. 본문의 h1 이 「주간 편성표」 하나
  5. head 안에 css/style.css 를 잇는 link (rel="stylesheet")

흔한 오답 — 「head 안에 css/style.css 를 잇는 link (rel="stylesheet")」에서 걸립니다

주소(href)만 맞으면 될 것 같지만, rel="stylesheet" 가 없으면 브라우저가 «무엇을» 잇는지 몰라 CSS 를 통째로 무시합니다. 오류도 안 납니다.

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>주간 편성표</title>
  <link href="css/style.css">
</head>
<body>
  <h1>주간 편성표</h1>
</body>
</html>

문제 6. 링크 안의 사진

코드 작성 · HTML (body 안에 들어갈 내용)

문제

기사 사진 photo.jpg 를 누르면 detail.html 로 가도록 만드시오. 사진의 대체 글은 폭설로 멈춘 버스 입니다. (미리보기에는 사진 파일이 없어 대체 글이 보입니다 — 그게 정상입니다)

정답

<a href="detail.html">
  <img src="photo.jpg" alt="폭설로 멈춘 버스">
</a>

해설

a 안에는 글자뿐 아니라 사진도 넣을 수 있습니다 — 사진 전체가 누를 수 있는 링크가 됩니다. alt 는 사진을 못 볼 때(사진 파일이 없을 때 · 화면 읽기 프로그램) 대신 쓰이는 글입니다. 특히 링크 안의 사진은 alt 가 곧 링크의 이름이라, 빠뜨리면 「어디로 가는 링크인지」를 알 수 없습니다.

검사 항목 (3개)

  1. detail.html 로 가는 링크 안에 img 가 있다
  2. 사진 주소가 photo.jpg
  3. 대체 글(alt)이 「폭설로 멈춘 버스」

흔한 오답 — 「대체 글(alt)이 「폭설로 멈춘 버스」」에서 걸립니다

사진이 잘 보이면 alt 를 빠뜨려도 티가 나지 않습니다.

<a href="detail.html">
  <img src="photo.jpg">
</a>

문제 7. 두 단계 위로 — 경로

개념 확인 · 답 적기

문제

폴더가 이렇게 되어 있습니다.

site/
├─ assets/
│   └─ cover.png
└─ shows/
    └─ 2024/
        └─ ep01.html

shows/2024/ep01.html 에서 표지 그림을 띄우려 합니다. <img src="?"> 의 ? 에 쓸 상대 경로를 적으시오.

정답 — ../../assets/cover.png (./../../assets/cover.png 도 정답)

해설

경로는 그 HTML 파일이 있는 폴더(shows/2024/)에서 출발합니다. ../ 한 번에 한 칸씩 올라갑니다. ../ → shows/, ../../ → site/, 거기서 assets/cover.png 로 내려갑니다. 그래서 ../../assets/cover.png 입니다.

흔한 오답 — ../assets/cover.png

../ 를 한 번만 쓰면 shows/ 까지만 올라가서 shows/assets/cover.png 를 찾습니다. 파일이 «두 겹» 안에 있다는 것을 세지 않은 경우입니다.

문제 8. 이어지지 않은 글자표

오류 고치기 · HTML (body 안에 들어갈 내용)

문제

공연 예매 오픈 알림을 신청하는 폼입니다. 그런데 글자표 「이름」「이메일」을 눌러도 칸에 커서가 가지 않습니다.

  • 두 글자표가 각자 자기 칸과 이어지게 고치시오
  • 이메일 칸은 이메일 형식 칸(type="email")으로 바꾸시오 (미리보기에서 버튼을 눌러도 아무 데도 보내지 않습니다)

시작 코드

<form>
  <label for="name">이름</label>
  <input type="text" id="username">
  <label>이메일</label>
  <input type="text" id="mail">
  <button type="submit">알림 신청</button>
</form>

정답

<form>
  <label for="name">이름</label>
  <input type="text" id="name">
  <label for="mail">이메일</label>
  <input type="email" id="mail">
  <button type="submit">알림 신청</button>
</form>

해설

label 의 for 와 input 의 id 가 글자까지 같아야 이어집니다(name ≠ username). 이어지면 글자표를 눌러도 칸이 선택되고, 화면 읽기 프로그램이 칸의 이름을 읽어 줍니다. type="email" 은 제출할 때 「@」가 없으면 막아 주고, 휴대폰에서는 @ 가 있는 자판을 띄웁니다. <label>이메일 <input …></label> 처럼 감싸도 이어집니다.

검사 항목 (4개)

  1. 「이름」 글자표가 칸과 이어져 있다
  2. 「이메일」 글자표가 칸과 이어져 있다
  3. 「이메일」 칸이 이메일 형식(type=email)
  4. form 안에 「알림 신청」 버튼

흔한 오답 — 「「이메일」 글자표가 칸과 이어져 있다」에서 걸립니다

「이름」만 고치고 나면 다 된 것 같습니다. for 가 아예 없는 「이메일」 글자표는 칸 바로 옆에 있어도 남남입니다 — 글자표를 하나씩 눌러 보면 압니다.

<form>
  <label for="name">이름</label>
  <input type="text" id="name">
  <label>이메일</label>
  <input type="email" id="mail">
  <button type="submit">알림 신청</button>
</form>

문제 9. 머리 줄이 섞인 표

오류 고치기 · HTML (body 안에 들어갈 내용)

문제

팟캐스트 회차 표에 잘못된 곳이 두 군데 있습니다. 고치시오.

  • 머리 줄(회차 · 제목 · 재생 수)이 몸통(tbody) 안에 들어가 있다 → 머리 줄은 thead 로
  • 13회 줄은 칸이 하나 모자란다 → 13회의 재생 수는 7,302

시작 코드

<table>
  <tbody>
    <tr><th>회차</th><th>제목</th><th>재생 수</th></tr>
    <tr><td>12</td><td>첫 출근 브이로그</td><td>8,420</td></tr>
    <tr><td>13</td><td>편집실의 하루</td></tr>
    <tr><td>14</td><td>라이브 뒷이야기</td><td>6,915</td></tr>
  </tbody>
</table>

정답

<table>
  <thead>
    <tr><th>회차</th><th>제목</th><th>재생 수</th></tr>
  </thead>
  <tbody>
    <tr><td>12</td><td>첫 출근 브이로그</td><td>8,420</td></tr>
    <tr><td>13</td><td>편집실의 하루</td><td>7,302</td></tr>
    <tr><td>14</td><td>라이브 뒷이야기</td><td>6,915</td></tr>
  </tbody>
</table>

해설

thead 를 안 쓰면 브라우저가 몰래 tbody 하나에 모든 줄을 넣습니다(F12 의 Elements 에 보입니다). 그러면 「어느 줄이 머리인가」가 태그로 드러나지 않고, 머리 줄만 꾸미기도 어렵습니다. 줄마다 칸 수가 다르면 표가 들쭉날쭉해집니다. 브라우저는 오류를 내지 않으므로 세어 보는 수밖에 없습니다.

검사 항목 (4개)

  1. 머리 줄(thead)에 칸(th) 3개
  2. 몸통(tbody)에는 회차 3줄만
  3. 몸통 줄마다 칸이 3개
  4. 13회 줄의 재생 수가 7,302

흔한 오답 — 「몸통 줄마다 칸이 3개」에서 걸립니다

칸이 모자란 줄도 브라우저는 오류 없이 그립니다 — 오른쪽 끝이 비어 있을 뿐이라 눈에 잘 안 띕니다. 줄마다 칸 수를 세어 보는 습관이 필요합니다.

<table>
  <thead>
    <tr><th>회차</th><th>제목</th><th>재생 수</th></tr>
  </thead>
  <tbody>
    <tr><td>12</td><td>첫 출근 브이로그</td><td>8,420</td></tr>
    <tr><td>13</td><td>편집실의 하루</td></tr>
    <tr><td>14</td><td>라이브 뒷이야기</td><td>6,915</td></tr>
  </tbody>
</table>

문제 10. 클래스 선택자

빈칸 채우기 · CSS

문제

기사 제목(title 클래스)만 글자 색을 #0d6b75 로 바꾸려 합니다. 「많이 본 기사」 제목은 그대로 둡니다. 빈칸(___)에 알맞은 선택자를 채우시오.

HTML (고정)

<h2 class="title">금리 동결</h2>
<p>한국은행이 기준금리를 동결했다.</p>
<h2>많이 본 기사</h2>
<h2 class="title">신작 개봉</h2>

시작 코드

___ {
  color: #0d6b75;
}

정답

.title {
  color: #0d6b75;

  4. 곁이 본문 오른쪽, 폭 250px
  5. 바닥이 맨 아래, 폭 1000px
  6. Grid 의 grid-template-areas 로 풀었다

.page {

  grid-template-areas:
    "header header"
    "nav    nav"
    "main   main"
    "footer footer";
}
header { grid-area: header; }
nav    { grid-area: nav; }
main   { grid-area: main; }
footer { grid-area: footer; }

화면은 같아도 오답 — 「Grid 의 grid-template-areas 로 풀었다」에서 걸립니다

줄 번호(grid-column: 1 / -1)로도 같은 배치가 나오지만, 이 문제는 grid-template-areas 로 그림처럼 그리는 것을 묻습니다.
