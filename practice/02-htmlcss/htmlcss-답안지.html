문제 1. 문서 뼈대

문제

다음 조건을 지키는 HTML 문서를 처음부터 작성하시오.

  • 문서 형식 선언(<!DOCTYPE html>)
  • 언어는 한국어(lang="ko")
  • 문자 인코딩은 UTF-8
  • 탭에 보이는 제목은 오늘의 뉴스
  • 본문에 h1 하나: 오늘의 뉴스

정답

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>오늘의 뉴스</title>
</head>
<body>
  <h1>오늘의 뉴스</h1>
</body>
</html>

해설

<!DOCTYPE html> 은 「이 문서는 지금의 HTML 규칙으로 그려 달라」는 표시입니다. 빠뜨려도 글자는 똑같이 보여서 알아차리기 어렵지만, 브라우저가 호환 모드로 그려 상자 크기 계산 같은 것이 옛날 방식이 됩니다. <meta charset="utf-8"> 이 없으면 서버 설정에 따라 한글이 깨질 수 있습니다. <head> 의 맨 앞쪽에 둡니다.

검사 항목 (5개)

  1. 맨 첫 줄이 문서 형식 선언()
  2. html 의 lang 이 ko
  3. meta charset 이 utf-8
  4. 탭 제목이 「오늘의 뉴스」
  5. 본문의 h1 이 「오늘의 뉴스」 하나

흔한 오답 — 「맨 첫 줄이 문서 형식 선언()」에서 걸립니다

화면은 똑같이 나와서 빠뜨린 줄 모릅니다. 선언이 없으면 브라우저가 옛날 규칙(호환 모드)으로 그려 박스 크기 계산이 달라집니다.

<html lang="ko">
<head>
  <meta charset="utf-8">
  <title>오늘의 뉴스</title>
</head>
<body>
  <h1>오늘의 뉴스</h1>
</body>
</html>

문제 2. 시맨틱 배치

문제

뉴스 사이트의 큰 틀을 이름이 있는 상자(시맨틱 태그)로 만드시오.

  • body 바로 아래에 차례대로 머리 · 메뉴 · 본문 · 바닥 네 상자
  • 상자마다 안에 글자를 아무거나 넣을 것 (예: 오늘의 뉴스, 정치 경제 사회, 기사 목록, © 오늘의 뉴스)

정답

<header>오늘의 뉴스</header>
<nav>정치 경제 사회</nav>
<main>기사 목록</main>
<footer>© 오늘의 뉴스</footer>

해설

div 로 다 만들어도 화면은 같습니다. 그런데 <div class="header"> 의 header 는 사람만 읽는 이름이고, <header> 는 브라우저 · 화면 읽기 프로그램 · 검색 엔진도 읽는 이름입니다. nav 를 header 안에 넣는 것도 흔하고 틀린 것은 아니지만, 이 문제는 「body 바로 아래 네 개」를 요구합니다.

검사 항목 (2개)

  1. body 바로 아래가 header → nav → main → footer
  2. 네 상자 모두 안에 글자가 있다

흔한 오답 — 「body 바로 아래가 header → nav → main → footer」에서 걸립니다

화면은 똑같습니다. 하지만 class 이름은 사람만 읽고, 화면 읽기 프로그램 · 검색 엔진은 태그 이름을 읽습니다.

<div class="header">오늘의 뉴스</div>
<div class="nav">정치 경제 사회</div>
<div class="main">기사 목록</div>
<div class="footer">© 오늘의 뉴스</div>

문제 3. strong 과 b

문제

기사 본문에서 「오늘 오후 3시부터 운행 중단」은 독자가 꼭 알아야 할 중요한 내용이라 굵게 보이게 하려 합니다. 가장 알맞은 것은?

① <b> — 굵게 보이기만 하면 된다
② <strong> — 「중요하다」는 뜻을 담는다
③ <h3> — 크고 굵게 보인다
④ <br> 으로 앞뒤를 끊어 눈에 띄게 한다

정답 — ② <strong> — 「중요하다」는 뜻을 담는다

해설

<b> 와 <strong> 은 화면이 같습니다. 다른 것은 뜻입니다 — <strong> 은 「중요하다」를 담아 화면 읽기 프로그램이 힘주어 읽고, <b> 는 「굵게 보일 뿐」입니다. <h3> 은 제목이라 문서의 목차(구조)가 바뀌고, <br> 은 줄을 바꿀 뿐 강조가 아닙니다.

흔한 오답 — ①

화면에서는 <b> 와 <strong> 이 똑같이 굵습니다. 그래서 짧은 <b> 를 고르기 쉽습니다.

문제 4. 순위 목록

문제

「많이 본 기사」 1~3위를 순서가 있는 목록으로 만드시오. 항목은 차례대로 금리 동결, 신작 개봉, 폭설 주의보 입니다.

정답

<ol>
  <li>금리 동결</li>
  <li>신작 개봉</li>
  <li>폭설 주의보</li>
</ol>

해설

ul 은 순서 없는 목록(점), ol 은 순서가 있는 목록(번호)입니다. 번호를 글자로 직접 쓰지 않아도 ol 이 1, 2, 3 을 붙여 줍니다. 순위 · 절차처럼 순서를 바꾸면 뜻이 달라지는 것은 ol 입니다.

검사 항목 (3개)

  1. ol 안에 li 가 3개
  2. 순서 없는 목록(ul)을 쓰지 않았다
  3. 항목이 금리 동결 / 신작 개봉 / 폭설 주의보 차례

흔한 오답 — 「ol 안에 li 가 3개」에서 걸립니다

목록이면 ul 부터 떠올리기 쉽습니다. 순위처럼 순서에 뜻이 있으면 ol 입니다.

<ul>
  <li>금리 동결</li>
  <li>신작 개봉</li>
  <li>폭설 주의보</li>
</ul>

문제 5. 이름–값 목록

문제

기사 정보 세 가지를 이름–값 목록(dl)으로 만드시오.

  • 기자 — 김하나
  • 날짜 — 2024-11-05
  • 조회수 — 1,204

정답

<dl>
  <dt>기자</dt><dd>김하나</dd>
  <dt>날짜</dt><dd>2024-11-05</dd>
  <dt>조회수</dt><dd>1,204</dd>
</dl>

해설

dl(목록) 안에 dt(이름)와 dd(값)를 짝지어 차례로 씁니다. 기사 정보 · 상품 정보처럼 「항목: 값」이 이어지는 곳에 씁니다. dd 는 기본으로 왼쪽이 들여 쓰여 보입니다 — 모양은 CSS 로 바꾸면 됩니다.

검사 항목 (3개)

  1. dl 이 하나 있다
  2. dt 3개 · dd 3개
  3. 짝이 기자=김하나 · 날짜=2024-11-05 · 조회수=1,204

흔한 오답 — 「dl 이 하나 있다」에서 걸립니다

「목록」이라 ul 로 쓰기 쉽습니다. 이름과 값이 «짝»이면 dl 이 그 짝을 태그로 드러냅니다.

<ul>
  <li>기자: 김하나</li>
  <li>날짜: 2024-11-05</li>
  <li>조회수: 1,204</li>
</ul>

문제 6. 링크 안의 사진

문제

기사 사진 photo.jpg 를 누르면 detail.html 로 가도록 만드시오. 사진의 대체 글은 폭설로 멈춘 버스 입니다. (미리보기에는 사진 파일이 없어 대체 글이 보입니다 — 그게 정상입니다)

정답

<a href="detail.html">
  <img src="photo.jpg" alt="폭설로 멈춘 버스">
</a>

해설

a 안에는 글자뿐 아니라 사진도 넣을 수 있습니다 — 사진 전체가 누를 수 있는 링크가 됩니다. alt 는 사진을 못 볼 때(사진 파일이 없을 때 · 화면 읽기 프로그램) 대신 쓰이는 글입니다. 특히 링크 안의 사진은 alt 가 곧 링크의 이름이라, 빠뜨리면 「어디로 가는 링크인지」를 알 수 없습니다.

검사 항목 (3개)

  1. detail.html 로 가는 링크 안에 img 가 있다
  2. 사진 주소가 photo.jpg
  3. 대체 글(alt)이 「폭설로 멈춘 버스」

흔한 오답 — 「대체 글(alt)이 「폭설로 멈춘 버스」」에서 걸립니다

사진이 잘 보이면 alt 를 빠뜨려도 티가 나지 않습니다.

<a href="detail.html">
  <img src="photo.jpg">
</a>

문제 7. 경로

문제

폴더가 이렇게 되어 있습니다.

site/
├─ index.html
├─ images/
│   └─ logo.png
└─ news/
    └─ list.html

news/list.html 에서 로고를 띄우려면 <img src="?"> 의 ? 에 무엇을 써야 합니까?

① images/logo.png
② ../images/logo.png
③ /images/logo.png
④ news/images/logo.png

정답 — ② ../images/logo.png

해설

경로는 그 HTML 파일이 있는 곳에서 출발합니다. list.html 은 news/ 안에 있으니, ../ 로 한 칸 올라가(site/) images/logo.png 로 내려갑니다. images/logo.png 는 news/images/logo.png 를 찾고, /images/logo.png 는 서버에 올렸을 때만(사이트 맨 위가 정해졌을 때만) 맞습니다 — 파일로 열면 깨집니다.

흔한 오답 — ③

/ 로 시작하면 「맨 위에서부터」라 맞아 보입니다. 하지만 파일을 더블클릭해 열면 맨 위가 site/ 가 아니라 디스크의 맨 위(C:)가 됩니다.

문제 8. 표

문제

분야별 기사 수를 표로 만드시오. 머리 줄(thead)과 몸통(tbody)을 나눕니다.

분야 기사 수 비율
사회 121 24.2%
정치 115 23.0%
경제 88 17.6%
스포츠 80 16.0%

정답

<table>
  <thead>
    <tr><th>분야</th><th>기사 수</th><th>비율</th></tr>
  </thead>
  <tbody>
    <tr><td>사회</td><td>121</td><td>24.2%</td></tr>
    <tr><td>정치</td><td>115</td><td>23.0%</td></tr>
    <tr><td>경제</td><td>88</td><td>17.6%</td></tr>
    <tr><td>스포츠</td><td>80</td><td>16.0%</td></tr>
  </tbody>
</table>

해설

th 는 머리 칸(굵게 · 가운데), td 는 데이터 칸입니다. thead · tbody 로 나누면 「어느 줄이 머리인가」가 태그로 드러나고, 나중에 CSS 로 머리 줄만 꾸미기도 쉽습니다. 🔴 tbody 를 안 써도 브라우저가 알아서 넣습니다(F12 의 Elements 에 보입니다). 그래서 thead 없이 쓰면 머리 줄까지 몸통 안에 들어갑니다.

검사 항목 (5개)

  1. 표가 하나 있다
  2. 머리 줄(thead)에 칸(th) 3개
  3. 몸통(tbody)에 4줄
  4. 몸통 줄마다 칸(td) 3개
  5. 첫 몸통 줄이 「사회」로 시작

흔한 오답 — 「머리 줄(thead)에 칸(th) 3개」에서 걸립니다

화면은 같습니다. 그런데 thead 를 안 쓰면 브라우저가 몰래 tbody 하나에 다섯 줄을 다 넣습니다 — F12 로 보면 보입니다.

<table>
  <tr><th>분야</th><th>기사 수</th><th>비율</th></tr>
  <tr><td>사회</td><td>121</td><td>24.2%</td></tr>
  <tr><td>정치</td><td>115</td><td>23.0%</td></tr>
  <tr><td>경제</td><td>88</td><td>17.6%</td></tr>
  <tr><td>스포츠</td><td>80</td><td>16.0%</td></tr>
</table>

문제 9. 폼

문제

뉴스레터 신청 폼을 만드시오.

  • 「이메일」 글자표(label)와 이메일 형식 입력 칸 — 글자표를 누르면 칸에 커서가 가도록 이어 붙일 것
  • 「신청」 버튼 (미리보기에서 버튼을 눌러도 아무 데도 보내지 않습니다)

정답

<form>
  <label for="email">이메일</label>
  <input type="email" id="email" name="email">
  <button type="submit">신청</button>
</form>

해설

label 의 for 와 input 의 id 를 같은 이름으로 쓰면 둘이 이어집니다. 글자표를 눌러도 칸이 선택되고, 화면 읽기 프로그램이 칸의 이름을 읽어 줍니다. (<label>이메일 <input …></label> 처럼 감싸도 이어집니다.) type="email" 은 제출할 때 「@」가 없으면 막아 주고, 휴대폰에서는 @ 가 있는 자판을 띄웁니다.

검사 항목 (4개)

  1. form 이 있다
  2. form 안에 이메일 형식 입력 칸
  3. 「이메일」 글자표가 입력 칸과 이어져 있다
  4. form 안에 「신청」 버튼

흔한 오답 — 「「이메일」 글자표가 입력 칸과 이어져 있다」에서 걸립니다

글자표가 칸 옆에 보이면 이어진 것 같지만, for 와 id 가 없으면 서로 남남입니다. 글자표를 눌러 보면 압니다.

<form>
  <label>이메일</label>
  <input type="email" name="email">
  <button type="submit">신청</button>
</form>

문제 10. 클래스 선택자

문제

기사 제목(title 클래스)만 글자 색을 #0d6b75 로 바꾸시오. 「많이 본 기사」 제목은 그대로 둡니다.

HTML (고정)

<h2 class="title">금리 동결</h2>
<p>한국은행이 기준금리를 동결했다.</p>
<h2>많이 본 기사</h2>
<h2 class="title">신작 개봉</h2>

정답

.title {
  color: #0d6b75;
}

해설

h2 는 모든 h2 를, .title 은 class="title" 인 것만 고릅니다. 같은 태그 중 일부만 꾸미고 싶을 때 클래스를 씁니다. 점(.)을 빠뜨리면 title 이라는 태그를 찾아 아무것도 안 바뀝니다.

검사 항목 (2개)

  1. .title 두 개의 글자 색이 #0d6b75
  2. 「많이 본 기사」(class 없는 h2)는 그대로

흔한 오답 — 「「많이 본 기사」(class 없는 h2)는 그대로」에서 걸립니다

제목이 다 h2 라 태그 이름으로 고르기 쉽습니다. 그러면 「많이 본 기사」까지 같이 바뀝니다.

h2 {
  color: #0d6b75;
}

문제 11. 자손 선택자

문제

메뉴(nav) 안의 링크만 밑줄을 없애시오. 바닥(footer)의 링크는 밑줄이 그대로 있어야 합니다.

HTML (고정)

<nav>
  <a href="#">정치</a>
  <a href="#">경제</a>
</nav>
<p>본문</p>
<footer>
  <a href="#">회사 소개</a>
</footer>

정답

nav a {
  text-decoration: none;
}

해설

선택자 사이의 띄어쓰기는 「안에 있는」이라는 뜻입니다. nav a 는 「nav 안에 있는 a」만 고릅니다. 바로 아래 자식만이 아니라 몇 겹 안에 있어도 고릅니다.

검사 항목 (2개)

  1. nav 안 링크의 밑줄이 없다
  2. footer 안 링크의 밑줄은 그대로

흔한 오답 — 「footer 안 링크의 밑줄은 그대로」에서 걸립니다

a 하나로 쓰면 짧고 메뉴도 잘 바뀌어서, 바닥 링크까지 바뀐 것을 못 보고 넘어갑니다.

a {
  text-decoration: none;
}

문제 12. 글자 꾸미기

문제

기사 본문 문단(.news 안의 p)을 이렇게 꾸미시오.

  • 글자 크기 18px
  • 줄 간격 1.6 (글자 크기의 1.6배)
  • 글자 색 #333333

HTML (고정)

<article class="news">
